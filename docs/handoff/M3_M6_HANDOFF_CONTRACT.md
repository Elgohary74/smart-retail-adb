## 2. Step-by-Step Extension Recipes for Future Waves

### 2.1 How to Build Milestone 3 (Vectorized Query Engine & Cost-Based Optimizer) on M1–M2

1. **Zero-Copy Columnar Batch Execution (`BATCH_SIZE <= 1020`):**
   * Obtain a `ColumnTableHeap` via `heap = engine.get_table("order_items")` (verify `isinstance(heap, ColumnTableHeap)`).
   * Stream only needed columns with `heap.iter_batches(columns=("product_id", "qty", "unit_price"))`. Each yielded `batch: dict[str, np.ndarray]` holds up to `CHUNK_ROWS = 1020` rows backed by zero-copy `ColumnPage.as_numpy_array()` views while buffer frames stay pinned inside `try/finally`.
   * Apply vectorized NumPy masks (`mask = (batch["qty"] >= 2) & (batch["unit_price"] <= 200.0)`) and reductions (`np.sum`, `np.bincount`) *inside* the loop body before advancing the generator (which unpins the current chunk). If a pipeline operator buffers rows across batches (e.g., `HashJoin` build side), copy the filtered slice (`arr[mask].copy()`).
2. **Cost-Based Optimizer (CBO) Plan Selection:**
   * Query `stats = catalog.get_table_stats(table_name)`. The returned dictionary provides exact fields:
     * `stats["row_count"]`: live tuple count
     * `stats["page_count"]`: physical page count (per column for `COLUMN`, total heap pages for `ROW`)
     * `stats["column_stats"][col]`: `{"min_val": ..., "max_val": ...}`
     * `stats["indexes"][idx_name]`: `{"column": ..., "type": "BPLUS_TREE"|"LSM_TREE", "unique": bool, "path": ...}`
   * Estimate selectivity using `(hi - lo) / (max_val - min_val)` for range predicates or `1 / row_count` for unique keys, then compare $C_{\text{scan}} = \text{page\_count} \times C_{\text{seq}}$ against $C_{\text{idx}}$ using `index.get_stats()` (`height` / `allocated_pages` on `BPlusTreeIndex`, `sstable_count` on `LSMTreeIndex`).
3. **Index Scan $\to$ Tuple Materialization:**
   * Execute `rids = index.get(key)` or `[rid for _, rid in index.range_scan(lo, hi, inclusive=True)]` (sorted by `RID` when beneficial for sequential page locality), then materialize rows via `heap.get(rid)` on either `RowTableHeap` or `ColumnTableHeap`.

### 2.2 How to Build Milestone 4 (MVCC Snapshot Isolation & ARIES Crash Recovery) on M1–M2

1. **In-Place MVCC Visibility & Tuple Versioning (`SlottedPage`):**
   * Every tuple inserted via `SlottedPage.insert_tuple(payload, xmin=1, xmax=0)` already begins with the 16-byte `<QQ` header (`xmin`, `xmax`) at tuple bytes `0..15`.
   * Inside `SlottedPage` (under an active `bpm.fetch_page(rid.page_id)` pin):
     * Read transaction bounds: `xmin, xmax = sp.get_tuple_mvcc_header(rid.slot_id)`.
     * Apply Snapshot Isolation visibility: `is_visible = (xmin <= snapshot_xmax and xmin not in active_txns) and (xmax == 0 or xmax > snapshot_xmax or xmax in active_txns)`.
     * Mark deletion / version retirement in place without shifting slots: `sp.set_tuple_xmax(rid.slot_id, txn_id)`, then unpin with `bpm.unpin_page(rid.page_id, is_dirty=True)`.
   * Never bypass `SlottedPage.insert_tuple` / `update_tuple` to overwrite tuple bytes `0..15` with user columns.
2. **ARIES `page_lsn` Tracking & WAL-Before-Dirty-Flush Hook (`PageHeader` + `BufferPoolManager`):**
   * Whenever M4 logs a physical/physiological redo record with `lsn`, stamp the pinned buffer before unpinning: `PageHeader.set_page_lsn(buf, lsn)`.
   * During ARIES Redo recovery, fetch the page and skip reapplication whenever `PageHeader.get_page_lsn(buf) >= log_record.lsn`.
   * Wire Write-Ahead Logging enforcement directly into `BufferPoolManager._flush_frame_if_dirty()` (`src/storage/buffer_pool.py`), which already marks the exact `# M4 ARIES WAL hook: enforce flushed_lsn >= PageHeader.get_page_lsn(frame.data)` boundary executed on both `flush_page()` and dirty victim eviction.
   * Note that `LSMTreeIndex` already maintains an independent CRC32-framed `lsm.wal` and atomic `manifest.json`; coordinate M4 transaction commit ordering so index mutations replay deterministically with heap redo/undo.

### 2.3 How to Build Milestone 5 (Distributed Sharding & 384-d Vector Search) on M1–M2

1. **Exact 384-Dimensional Cosine Similarity via `ColumnPage(..., stride=1536)`:**
   * `ColumnPage` supports arbitrary fixed-byte strides. Pass `stride = 384 * 4 = 1536` (`DataType.FLOAT64` or `DataType.INT32` tag as placeholder; `stride` overrides `dtype.fixed_size` cleanly):
     ```python
     cp = ColumnPage.init_page(buf, page_id, DataType.INT32, stride=1536)
     ```
   * Physical capacity per 8,192-byte page is `(8192 - 32) // 1536 = 5` vectors (`slot_count <= 5`).
   * Append `vec.astype(np.float32).tobytes()` (`1,536` bytes per vector) via `cp.append_value(...)` / `cp.append_batch(...)`, and read zero-copy batches while pinned:
     ```python
     mat = cp.as_numpy_array(np.float32).reshape(-1, 384)  # shape (N, 384), OWNDATA=False
     scores = (mat @ query_vec) / (np.linalg.norm(mat, axis=1) * np.linalg.norm(query_vec))
     ```
2. **Deterministic Sharding & Immutable `RID`s:**
   * Both `customers` and `orders` share `customer_id` (`INT64`) and `customers` carries `region` (`VARCHAR(16)`), allowing M5 `ShardRouter` nodes to co-locate customer and order partitions deterministically via `hash(shard_key) % num_shards` (or `zlib.crc32` for process-stable hashing across Python invocations, avoiding randomized `PYTHONHASHSEED`).
   * Because `SlottedPage.compact()` updates `tuple_offset` in place without renumbering `slot_id`, local shard `RID(page_id, slot_id)` pointers remain valid across page compactions.

## 3. Do-Not-Break Invariants Checklist

Future waves **must** preserve every invariant below:

- [ ] **32-Byte Universal Header (`<IBBHQIIQ`):** Bytes `0..31` of every `.db`, `.col`, and `.bpt` page must keep exact field widths (`page_id`, `page_type`, `flags`, `slot_count`, `page_lsn` at bytes `8..15`, `free_space_ptr`, `next_page_id`, `checksum` at bytes `24..31`).
- [ ] **64-Bit BLAKE2b Integrity Checksum:** Every persistent write through `DiskManager.write_page()` stamps `BLAKE2b(digest_size=8)` over `buf[0:24] + buf[32:8192]`. Never write directly to `.db`/`.col`/`.bpt` files bypassing `DiskManager`.
- [ ] **Page 0 FSM Offsets:** Heap/column files reserve bytes `0..31` (`fsm_offset=32`, max `65,280` data pages); `BPlusTreeIndex` reserves bytes `0..63` (`fsm_offset=64`, Page 0 `<IBHHQ?6x` metadata at `32..55`, max `65,024` data pages).
- [ ] **16-Byte MVCC Tuple Header (`<QQ`):** Every `SlottedPage` tuple begins with `(xmin: uint64, xmax: uint64)`. Callers reading raw `SlottedPage.get_tuple(..., include_mvcc=False)` receive user payload only; MVCC code must use `get_tuple_mvcc_header()` / `set_tuple_xmax()` or `include_mvcc=True`.
- [ ] **Immutable `RID(page_id, slot_id)`:** Never shift slot indices inside `SlottedPage.compact()` or `delete_tuple()`. Maintain lockstep `chunk_rows = 1020` across every `.col` file in `ColumnTableHeap`.
- [ ] **`BufferPoolManager` Pin-Count Discipline:**
  * Every `fetch_page()` or `new_page()` must have a matching `unpin_page(page_id, is_dirty=...)` in a `try/finally` block.
  * Never mutate a page without passing `is_dirty=True` on unpin.
  * `BPlusTreeIndex` traversals and splits must hold at most `2` frames pinned simultaneously (unpin parent/sibling before descending or advancing).
  * `new_page()` must secure/flush a buffer frame *before* allocating an FSM bit on disk.
- [ ] **Strict Lock Acquisition Order (Deadlock Prevention):**
  ```text
  StorageEngineLock -> CatalogLock -> IndexLock -> TableHeapLock -> BufferPoolLock -> DiskManagerLock
  StorageEngineLock -> ObjectStoreLock
  WorkloadAdvisorLock (leaf lock; never calls outward while held)
  ```
  Never acquire an earlier lock in this hierarchy while holding a later lock.
- [ ] **Key Encoding & Bloom Filter Scope:** Always use `encode_key()` for ordered index keys and `make_composite_key(user_key, rid)` for `BPlusTreeIndex` / `LSMTreeIndex` entries; hash **only** fixed-width `user_key` bytes into `SSTable` `BloomFilter`s.
