# Project & Developer Documentation Plan

**Goal:** Add clear, non-redundant documentation explaining the Smart Retail DB project, its codebase structure, and an explicit "where to start" onboarding path for developers.

**Existing Docs (Preserved, Not Duplicated):**
- `README.md` — Quick start, CLI/SQL syntax, Python snippet, benchmarks, directory tree.
- `docs/architecture.md` — Binary page formats, component contracts, design trade-offs, M3–M5 integration hooks.
- `docs/milestone-checklist.md` — M1/M2 verification checklist.

## Planned Files

### 1. Create `docs/project-overview.md` (Explaining the Project)
- **Purpose & Scope:** What Smart Retail DB is (custom CSAI 302 DBMS from scratch in pure Python stdlib), what it intentionally avoids (no SQLite/Postgres/DuckDB wrapper), and the 6-milestone roadmap (M1–M6).
- **Domain Model:** The Retail Orders tables (`Products`, `Customers`, `Orders`, `OrderItems`, `Inventory`) generated by `workloads/generate_retail_data.py` and how each milestone uses them.
- **End-to-End Request Lifecycle:** Plain-English walkthrough + Mermaid sequence diagram tracing a query (`INSERT` and `SELECT ... WHERE price BETWEEN ...`) from `cli.py` -> `query/parser.py` -> `engine/db.py` -> `indexes/` + `storage/` -> disk.
- **Understanding the Benchmarks:** Short guide explaining what M1 (`FIFO` vs `LRU`, `RowTable` vs `ColumnTable`, `page` vs `objects` vs AES-GCM) and M2 (`full_scan` vs `BPlusTree` vs `LSMTree`, write-heavy vs read-heavy, range scan) prove.

### 2. Create `docs/developer-guide.md` (Codebase Structure & Where to Start)
- **Where to Start (Ordered Reading Path):** Step-by-step 6-stage reading guide from lowest layer (`core/schema.py` -> `storage/backends/` & `buffer_pool.py` -> `storage/tables/` -> `indexes/` -> `query/` & `engine/db.py` -> `tests/` & `benchmarks/`), with exact file links and what to look for in each.
- **Package-by-Package Ownership Map:** Concise explanation of why `core/`, `storage/`, `indexes/`, `query/`, `engine/` are split the way they are, and which files are public API vs internal codecs.
- **Critical Engineering Invariants:** Rules devs must respect when modifying code (`with pool.pin_page(...)` so frames never leak pins, `validate_record` before disk writes, `bool` != `int`, SQL three-valued `NULL`, atomic `.tmp` + `os.replace` writes).
- **Common Developer Workflows & Where to Add M3–M5 Features:**
  - Running single tests vs full suite, using CLI `:explain` / `:stats`, running benchmarks.
  - Exact entry points for adding M3 (vectorized operators/joins/optimizer under `query/`), M4 (WAL/ARIES/locks under `engine/` + `BufferPool` LSN hooks), and M5 (exact top-k vector search & distributed nodes).

### 3. Update `README.md` (Documentation Links)
- Add a brief "Documentation" section near the top linking `docs/project-overview.md`, `docs/developer-guide.md`, `docs/architecture.md`, and `docs/milestone-checklist.md` so new readers/devs know immediately where to start.
